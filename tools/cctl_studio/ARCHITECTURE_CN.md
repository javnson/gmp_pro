# CCTL Studio 架构与生成计划

[English](ARCHITECTURE.md) | **简体中文**

## 已审阅的基线

当前仓库已经具备三层有效资产：数据驱动的 Xyce 原型、开关型 MNA 求解器与 C++
生成器，以及完整的 `ctl/suite/mcs_pmsm_nt/project/cctl` 闭环参考工程。参考工程
证明了数值和运行时链路，但它应当作为黄金集成样例，而不应把整个源文件原样套用到
所有图形工程。

适合作为自动生成输入的内容包括：

- 电路网表与求解器设置；
- SDPE 需求及工程私有硬件标定；
- 源码管理器模块选择；
- 元件实例、类型化端口、连线、参数、观测量、采样周期和执行顺序；
- 可复用的 CSP、外设、电路、电机和输出服务实现。

下列内容目前仍然硬编码，必须先转成元数据或可复用模板，参考工程才适合安全生成：

- `PmsmCircuit`、`PWM1..PWM6`、`VADC_*`、相序映射和七通道 ADC 约定；
- 三个 ePWM、一个 eQEP 的聚合方式及控制器寄存器绑定；
- 电机参数单位换算，以及主电路与电机之间的电流/电压耦合；
- 记录结构、CSV 列、采样率与探针路由；
- CMake 目标名、生成头/归档路径、后端选择和构建后部署；
- 当前直接认识 PMSM 相名与桥臂编号的校验规则。

`gmp_src_mgr/gmp_src`、生成的 SDPE 文件、生成的电路 JSON、矩阵归档和 C++ 计算类
均属于产物。Studio 工程、元件元数据、SDPE 需求、源码管理配置、网表和生成模板才是
源文件。

## 规范化图数据结构

TI Interconnect Studio 1.8 的可编辑示例是 SysConfig JavaScript，稳定概念包括
`scripting.addModule`、`addInstance`、属性赋值、
`scripting.connect(源, 端口, 目标, 端口)`、`$position` 和 `scripting.probe`。
CCTL Studio 应兼容这些语义，而不是复制 TI 的模块标识、实现代码或素材。

CCTL 的规范格式应继续采用不可执行的 JSON，至少包含：

- Schema/工具版本与工程元数据；
- 元件库引用；
- 带稳定 ID、模块 ID、显示名、坐标、参数和可选执行信息的实例；
- 显式连接对象，其中保存源/目标实例和端口 ID；
- 探针和结果流定义；
- 求解器、时序、后端和构建设置。

当前 schema-v1 电气格式把网络名写在每个实例端口里。它可以继续服务 Xyce 原型，
但不足以表达多域编辑器，因为端口方向、点到点控制连接、执行顺序和适配器都只能靠
猜测。Schema v2 应改用显式边；导入器可以把 v1 网络标签归一化为电气网络对象，
SysConfig 适配器则导入/导出语义兼容子集。TI `.syscfg` 是可执行 JavaScript，并引用
TI 私有模块目录，因此不追求也不应承诺字节级兼容。

每个端口必须声明域（`electrical`、`mechanical`、`analog_signal`、`digital` 或
`control`）、方向、数据类型、单位，以及必要时的速率约定。电压/电流互换和
ADC/PWM/编码器转换必须是显式适配器实例，不能作为连线的隐藏副作用。

执行信息应包含阶段和整数顺序，最少划分为 `pre_control`、`control`、`plant`、
`observe`。生成器校验同一阶段内编号唯一且依赖方向正确；未编号时使用确定性的拓扑
排序。一个 MNA 子网整体视为一个原子 plant 模块，不给每个电阻单独编号。

## 确定性生成流水线

```text
project.cctl.json + 元件库 + SDPE 需求
  -> Schema、类型、单位、速率、连通性和顺序校验
  -> 带稳定 ID 的规范化图
  -> MNA 网表/电路数据与 C++ 求解器
  -> CCTL 拓扑绑定、MCU 适配器、探针和输出结构
  -> 源码管理选择与 CMake 清单
  -> 编译、单元校验、生成模型校验和闭环回归
```

生成必须具备原子性、路径无关性和可复现性，并在覆盖最后一个正确产物前失败退出。
手写扩展点放在独立文件中；生成文件带明确标记，禁止反向手改。

## 后续阶段与验收门槛

1. **基础准备**：维护新的 `cctl/component` 目录、源码管理注册、基线测试和本参考
   约定。
2. **Schema v2 与元件目录**：发布 JSON Schema、稳定 ID、类型化端口、显式边、坐标、
   执行阶段/顺序、v1 迁移器，以及 MNA 子网、电机、适配器和外设元数据。
3. **无界面工程生成器**：在另一构建目录中由数据生成 PMSM 参考工程，不修改现有手写
   黄金样例；生成工程必须通过同一组增益、路由、编译和 4000 万步闭环回归。
4. **图形编辑器**：实现元件面板、属性检查器、画布连线、顺序编号、诊断、撤销/重做和
   确定性保存。界面只读写 schema-v2，并调用无界面生成器。
5. **Interconnect 适配器**：导入/导出兼容的 SysConfig 概念并增加往返测试；不支持的 TI
   属性要保存在命名空间扩展区或明确报错，不能静默丢失。
6. **发布**：打包工具、运行依赖、示例、迁移器和 CI 矩阵，明确 Schema 兼容范围及
   生成/源文件边界。

在 schema-v2 规范化器和无界面 PMSM 自动生成验收稳定前，不应先投入完整 UI。
这两层才是保证 UI、CLI、生成代码和后续导入器一致的核心契约。
